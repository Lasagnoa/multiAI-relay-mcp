## 問題の説明

`server.py` はプロジェクトパスをモジュールレベルのグローバル変数で管理している:

```python
_current_project: Path | None = None
```

`collab_switch_project()` を呼ぶたびにこの変数を書き換え、以降の全ツールがここを参照する設計になっている。

---

## 何が問題か（Whyのみ。Howは Codex が設計する）

1. **複数クライアントが同一プロセスに接続した場合**、プロジェクトパスが混在してデータが別プロジェクトに書き込まれる可能性がある（現状 uvx は Desktop ごとに別プロセスを起動するため実害は起きていないが、設計上の脆弱性）
2. **プロジェクトディレクトリが削除・移動された後**も `_current_project` は古いパスを保持し続け、エラーが `_state_file()` を呼ぶ時まで遅延する
3. ツール呼び出し元は「今どのプロジェクトが有効か」を知らずに操作している
